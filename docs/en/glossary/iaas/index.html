IaaS (infrastructure as a service): definition and examples

You rent virtual servers, disks and networking from a cloud provider and pay by use; you manage the operating system, the applications and the data yourself.

6
sections
6
questions answered

IaaS (infrastructure as a service) is the cloud model in which you rent virtual servers, storage and networking from a provider, on demand and billed by use, while you install and run the operating system, applications and data yourself. The reference definition, NIST SP 800-145 (September 2011), draws the line: the customer does not manage the underlying cloud infrastructure but controls operating systems, storage and deployed applications, plus, to a limited degree, some networking components such as host firewalls. IaaS is the layer with the most control and the most work; PaaS (the prepared platform, where you bring only the application) and SaaS (the finished application, where you bring only the users) sit above it.

A small company picks IaaS when it moves existing servers to the cloud without rewriting the applications (lift-and-shift), when it runs an old or Windows-only application that a platform will not host, or when it needs environments started only when needed. The trap: on IaaS, patching, backups and security stay with the customer. A server moved to the cloud and left unpatched is as exposed as one forgotten in the office.

Why it matters for your business

✓No capital tied up in hardware

Servers are rented by use and resized from the provider's console — capacity follows the business, not the depreciation cycle of a purchased server.

✓Full control of the environment

Any operating system, any configuration, any inherited application — the freedom of your own server, without the server room.

✓The quick way out of the building

A lift-and-shift migration moves existing systems to the cloud without rewrites — fire, theft and power-cut risk stay behind.

How IaaS works

In a provider's console or through its API you pick the region and the virtual machine type (number of vCPUs and amount of RAM), attach a disk (block storage), create the network (a private network, a public IP address, firewall rules) and start the machine from an operating system image. You pay for run time, storage used and traffic generated. Because everything is created through an API, the infrastructure can also be described as code (infrastructure as code), and a whole environment can be created and deleted on demand.

NIST SP 800-145 lists five essential characteristics of any cloud service, IaaS included: on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. In practice, nobody has to be called to get a server: you order it yourself in minutes and pay no more than you used. What happens on the server after it starts, from operating system updates to the installed application, stays your job.

Who manages what: on-premises, IaaS, PaaS, SaaS

Responsibility differs from one model to the next, and the providers' shared-responsibility pages (Microsoft Azure and Amazon Web Services) describe it the same way in essence. On-premises, everything is yours, from the building to the application. On IaaS, the provider is responsible for the data center, the physical servers, the physical network and virtualization; you are responsible for the operating system, the installed applications, configuration, data and the accounts that have access.

On PaaS, the provider also takes over the operating system, and you keep the application and the data. On SaaS, what remains is what nobody can take over for you: the data, the users with their permissions and the configuration. One rule applies in all four cases: the data, and who can access it, stay the customer's. That is why moving to the cloud does not move the responsibility for them.

IaaS vs VPS

A VPS (virtual private server) is usually sold as a fixed monthly plan: processor, memory, disk and traffic in a single package, managed from a panel. IaaS means components ordered separately and on demand — virtual machines, separate disks, private networks, snapshots, load balancers — created and deleted from the console or through the API and billed by use.

A VPS from a cloud provider is the simplest use of IaaS, so the short answer to “is a VPS IaaS?” is “in most cases, yes”. The difference matters when you want to scale, automate or pay only for the hours used. For a website or an online shop, the comparison of shared hosting, VPS and cloud by symptom has a separate page in the Comparisons section.

IaaS examples and when a company picks it

Examples of IaaS services: Amazon EC2, Azure Virtual Machines, Google Compute Engine, Hetzner Cloud and OVHcloud Public Cloud. All of them offer virtual machines and disks ordered on demand; they differ in regions, prices and surrounding services.

A company typically picks IaaS for an ERP or an old application moved as it is, for server software that runs only on Windows, for test or staging environments switched off outside working hours, or for special operating system and network requirements. On lock-in: virtual machine images and standard Linux or Windows systems move between providers more easily than platform-specific services. Data egress fees and the EU Data Act are covered in the comparison “Romanian cloud or hyperscaler”.

Frequently asked questions

What does IaaS mean?

IaaS stands for infrastructure as a service. A provider gives you virtual servers, disks and networking, on demand and billed by use. You administer the operating system, applications and data as on a server of your own, but with no physical hardware to maintain.

What is the difference between IaaS, PaaS and SaaS?

The difference is how much you administer yourself. SaaS is the finished application, PaaS is the platform your application runs on, IaaS is the bare servers. Many companies mix them: email on SaaS, their own application on PaaS, the old ERP on IaaS.

Is a VPS also IaaS?

In most cases, yes: a VPS from a cloud provider is a rented virtual server, which is IaaS in its simple form. The difference is how it is sold. A VPS comes as a fixed monthly plan, classic IaaS is ordered by component and billed by use.

Who handles security on IaaS, me or the provider?

Both, for different parts. The provider secures the data center, hardware, physical network and virtualization. The operating system, firewall, access, passwords, backups and data belong to the customer, according to the shared-responsibility pages of Microsoft and Amazon Web Services.

How much does an IaaS server cost?

A VPS for online shops and medium traffic: about 20–80 € a month; managed cloud for serious applications: 50–300 € a month. Your own server adds power, cooling, a UPS, replacements and the hours of the person who administers it.

Can I move an existing server to IaaS without rewriting the application?

Yes, through lift-and-shift: you copy the virtual machine or disk, or reinstall the same operating system and application on a cloud virtual machine. Then check licences on virtual hardware, IP addresses, backups and latency to the office.
