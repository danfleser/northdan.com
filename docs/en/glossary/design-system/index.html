Design system: what it contains and how it differs from a style guide

The collection of reusable rules and visual components a team builds interfaces from: buttons, colours, typography, spacing and the guidance for using them.

7

6
questions answered

A design system is the documented, maintained set of design tokens (colours, type, spacing), coded interface components and usage rules that designers and developers build every screen of a product from; public examples include Google's Material Design, IBM's Carbon and Shopify's Polaris. Count how many slightly different blue buttons live across your website, your customer portal and your mobile app. In most companies the honest answer is more than one, each drawn from scratch by whoever was on the project that quarter, each behaving a little differently on a phone. A design system is the antidote: one set of building blocks implemented once in real code and reused everywhere, with written guidance on when each is appropriate. It is not a style guide sitting in a slide deck; the components are the deliverable and the documentation exists to explain them.

The commercial argument is compounding rather than immediate. The first project pays for the system and gains little. From the second onward, new screens get assembled rather than drawn, accessibility and keyboard behaviour are inherited instead of re-argued, and a brand refresh becomes a change to shared values rather than a hunt through every page. For a company that expects to keep building, that is the difference between owning an asset and repeatedly renting one.

Why it matters for your business

✓New screens in days, not weeks

Assembling from tested components removes the design, build and review cycle that every fresh interface element otherwise triggers.

✓One brand at any scale

Website, portal and app stay visually identical even when different teams or suppliers work on them in different years.

✓Accessibility solved once

Contrast, focus order and keyboard support are built into the components, so every new screen inherits them by default.

What a design system is made of

A design system has five parts. Design tokens are name-value pairs, for example colour-primary = #0B5FFF, for colours, type, spacing and shadows. Components are pieces such as a button, text field, table or dialog, with states (default, pressed, disabled, error), variants and code. Patterns are groups of components that solve a task, such as a contact form or a page header.

Usage guidelines say when to pick each piece and when not to, what tone the copy takes and which accessibility requirements apply. The fifth part is people: according to Nielsen Norman Group, a design system is not only the repository of parts but also the team that maintains it. Since 28 October 2025 tokens have a standard format, the Design Tokens Format Module 2025.10 from the W3C Design Tokens Community Group, designed to be readable by different tools.

Design system vs style guide vs UI kit

A style guide is the document of visual and content rules; according to Nielsen Norman Group it is part of the design system, in a parent-child relationship. A UI kit is a set of components drawn in a design tool such as Figma, with no code and no usage rules. A brand manual describes identity (logo, palette, tone) and is the source the tokens start from.

The practical point: with only a UI kit, a developer redraws every component in code and the versions drift apart. A design system keeps design and code together. In short, UI is what you see and UX is how it works for a person; the design system ties both together.

Public examples: Material, HIG, Carbon, Polaris

Material Design (Google) covers Android and the web. Apple's Human Interface Guidelines are guidance for iOS and macOS, not a code library for the web. IBM's Carbon offers coded components and accessibility guidance. Shopify's Polaris is, according to shopify.dev, a UI framework built on web components.

Small companies adopt or adapt an existing system rather than build their own. Nielsen Norman Group describes three routes: adopt, adapt or create, with cost rising as customisation grows.

Accessibility built into components: the European Accessibility Act

Directive (EU) 2019/882, the European Accessibility Act, applies from 28 June 2025 and covers, among others, consumer e-commerce services. Microenterprises providing services are exempt. If your company is in scope, accessibility has to be in the product, not a task for the last week before launch.

Contrast, visible focus and keyboard navigation set once in a button or field reach every screen. The technical reference is WCAG. A design system makes compliance easier to reach but does not guarantee it on its own: each page still needs checking.

From tokens to code: CSS variables and Tailwind

In code, tokens become CSS variables. In Tailwind CSS v4 they are declared in an @theme block and directly generate utility classes: --color-brand-500 becomes bg-brand-500, text-brand-500 and so on. A colour change is then made in one place.

It is not always worth it. For a prototype or a brochure site that will not grow, Nielsen Norman Group notes that a proof of concept gets no near-term return from this effort. The more often a product changes and the more people work on it, the faster the system pays back.

Frequently asked questions

How does a design system differ from a brand manual?

A brand manual describes intent in a document: logo clearances, palette, tone of voice. A design system delivers working code — a button a developer imports, with its states, sizes and accessibility behaviour already decided. The manual tells you what good looks like; the system makes producing anything else the harder option.

Is a design system worth it for a single website?

For one small brochure site, no — the overhead outweighs the return. Nielsen Norman Group notes that a prototype or proof of concept gets no near-term return. It starts paying when you have a second surface: a customer portal, a mobile app, a partner extranet, or a site that will keep growing for years with rotating suppliers.

Which well-known design systems can we learn from?

Publicly documented examples are worth reading before commissioning your own: Google's Material Design, IBM's Carbon, Atlassian's system, Shopify's Polaris and the UK Government Design System. The last is instructive because it publishes research notes for many of its components, which is the part most internal systems skip.

What are design tokens?

Design tokens are name-value pairs for colours, type, spacing and shadows, used in both design and code. At a rebrand you change the value in one place. Since 28 October 2025 a standard format exists, the Design Tokens Format Module 2025.10.

Who maintains a design system?

One person or a small team, usually a designer and a front-end developer, who approve new components and publish versions. Without maintenance, components get duplicated and the system is abandoned; Nielsen Norman Group describes a dedicated team.

Is it better to adapt an existing design system or build one from scratch?

Adopting an existing one is the cheapest route, and cost rises the more you customise it. Building your own pays off when you have needs open-source systems do not cover, such as a very specific brand or several applications.
