Ce este o cheie API (API key)?

Un cod secret prin care o aplicație se identifică atunci când folosește serviciile alteia — parola dintre programe.

6
secțiuni
5
întrebări cu răspuns

O cheie API (API key) este un șir unic de caractere, generat de un serviciu online, pe care aplicația ta îl trimite la fiecare cerere ca furnizorul să știe cine cere, ce are voie și cât a consumat. E ca un card de acces de la hotel: îți deschide camera ta și sala de fitness la orele permise, iar recepția îl poate dezactiva oricând. Când aplicația ta cere date de la un serviciu extern (curier, procesator de plăți, hărți), prezintă cheia. Pe cheie se leagă facturarea, limitele de trafic și permisiunile. De ce te privește direct: cheile API sunt echivalentul parolelor firmei și ținta preferată a atacatorilor — o cheie de plăți scursă pe internet înseamnă bani cheltuiți în contul tău. Regulile de igienă sunt clare: cheile nu se pun niciodată în codul public al site-ului, se păstrează în manageri de secrete, se rotesc periodic și primesc doar permisiunile minime necesare. Merită să ceri echipei tale dovada că le respectă.

Termenul te interesează pentru un proiect concret? Gestionăm integrări și chei în siguranță — vezi serviciul de integrare API

De ce contează pentru afacerea ta

✓Control granular asupra accesului

Fiecare integrare primește propria cheie, cu exact permisiunile de care are nevoie — compromiterea uneia nu deschide toate ușile, iar revocarea se face punctual.

✓Trasabilitate și facturare corecte

Consumul fiecărei chei se măsoară separat — vezi exact ce integrare generează costuri, cine abuzează și unde se duc banii din abonamentele API.

✓Incidente oprite dintr-o mișcare

La orice suspiciune de scurgere, cheia se revocă și se emite alta în minute — fără schimbări de parole ale angajaților și fără oprirea celorlalte integrări.

Cum arată și cum se trimite o cheie API

O cheie arată ca un șir lung de caractere, adesea cu un prefix care îi spune tipul, de exemplu sk_live_… la Stripe. Aplicația o trimite la fiecare cerere, într-un antet HTTP (header), niciodată în adresa URL (?apiKey=…): adresele ajung în jurnalele serverelor, iar cheia ar rămâne scrisă acolo. Cheia leagă cererea de un proiect sau un cont, pentru facturare și cote.

Atenție la limită: o cheie obișnuită identifică aplicația, nu o persoană. Pentru acces la datele unui utilizator anume se folosește OAuth, iar pentru resurse sensibile cheia singură nu ajunge.

Cheie publică, cheie secretă, cheie de test

Exemplu la Stripe: cheia publicabilă (pk_…) poate sta în codul din browser, pentru că nu poate crea plăți și nu poate citi datele contului. Cheia secretă (sk_…) și cheia restricționată (rk_…) rămân doar pe server. Prefixele _test_ și _live_ separă cheile de test de cele de producție, iar obiectele create într-un mod nu apar în celălalt.

Cheile Google pentru browser (de exemplu Maps) stau în codul paginii, deci se protejează prin restricții de referrer HTTP, IP sau aplicație și prin restricții de API. Google spune: cheile fără restricții sunt nesigure. Regula simplă: tot ce se vede în browser e public, iar acolo intră doar o cheie făcută să fie publică.

Unde găsești sau cum generezi o cheie API

Pașii sunt aceiași la majoritatea furnizorilor: intri în contul furnizorului, deschizi secțiunea de dezvoltatori, API sau setări, alegi „Create key”, îi dai un nume și permisiunile minime, apoi o copiezi imediat. Multe servicii o arată o singură dată: Stripe nu mai permite afișarea unei chei live pe care ai creat-o. O cheie pierdută nu se recuperează, se înlocuiește (se rotește).

Păstreaz-o într-un manager de secrete sau într-o variabilă de mediu pe server, nu în cod și nu într-un document, și notează unde ai salvat-o. Folosește o cheie separată pentru fiecare integrare și fiecare mediu.

Ce faci dacă o cheie API a scăpat

1) Revocă sau rotește cheia imediat; la o scurgere alegi expirarea „Now”, nu o perioadă de grație (la Stripe, de până la 7 zile) ca la o rotație planificată. 2) Pune cheia nouă în managerul de secrete și publică din nou aplicația (redeploy). 3) Verifică în jurnalul de cereri al furnizorului ce a făcut cheia veche. 4) Șterge-o din cod și din istoricul Git, dar tratează-o ca fiind compromisă și după ștergere.

5) Dacă cheia dădea acces la date personale, se aplică regulile pentru încălcarea securității datelor, cu notificare în cel mult 72 de ore. Procedura e pe pagina Breșă de date, iar sistemele noastre de integrare API țin cheile în afara codului.

Întrebări frecvente

Care e diferența dintre o cheie API și un token OAuth?

Cheia identifică o aplicație și e de regulă statică, pe termen lung; token-ul OAuth reprezintă acordul unui utilizator concret, expiră repede și poartă permisiuni fine. Pentru integrări server-server se folosesc chei; pentru acces la datele clienților, OAuth.

Cum s-a putut «scurge» o cheie API pe internet?

Cel mai des prin publicarea accidentală în cod pe GitHub sau în JavaScript-ul vizibil al site-ului. GitHub scanează depozitele publice și anunță furnizorul când găsește o cheie cu formatul lui. Orice cheie care a apărut public se tratează ca fiind compromisă, chiar dacă ai șters-o.

Cât de des ar trebui rotite cheile API?

La intervalul stabilit de politica ta de securitate, imediat când pleacă sau își schimbă rolul cineva cu acces la ele și instant la orice suspiciune. Rotația periodică limitează paguba unei chei despre care nimeni nu știe că a scăpat. Procedura trebuie exersată dinainte.

Pot pune cheia API în codul site-ului sau al aplicației mobile?

Numai o cheie făcută să fie publică: cheia publicabilă Stripe (pk_) sau o cheie Google pentru browser, restricționată pe domeniu. Cheile secrete (sk_) rămân pe server: site-ul sau aplicația cheamă serverul tău, iar serverul cheamă furnizorul. Tot ce ajunge în browser sau în aplicația instalată poate fi extras.

Pot trimite cheia API pe e-mail sau WhatsApp unui colaborator?

Nu. Stripe recomandă să nu trimiți chei pe e-mail, chat sau alte canale necriptate. Dă colaboratorului propria cheie, cu permisiuni minime, printr-un manager de secrete sau de parole, iar când se termină lucrarea o revoci. Mesajele rămân în arhive și pe telefoane.
