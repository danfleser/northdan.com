Ce este un feature flag (feature toggle)?

Un întrerupător în cod care aprinde sau stinge o funcționalitate din aplicație, fără o nouă lansare și fără intervenția programatorilor.

Un feature flag (numit și feature toggle; în română, aproximativ „comutator de funcționalitate”) este o condiție din cod, evaluată în timpul rulării, care pornește sau oprește o funcționalitate deja livrată, pentru toți utilizatorii, pentru un procent sau pentru un client anume, fără o nouă lansare. Funcționalitatea nouă e livrată în aplicație, dar stă stinsă până când decizi tu să o aprinzi. Astfel, lansarea tehnică (codul ajunge în producție) se desparte de lansarea de business (clienții văd noutatea). Dacă apare o problemă, stingi comutatorul în secunde, fără redeploy și fără noapte albă pentru echipă.

Pentru firma ta, flag-urile înseamnă experimente controlate — testezi o schimbare pe un grup mic și măsori efectul înainte să o dai tuturor — plus un risc de lansare drastic redus. Sunt mecanismul prin care echipele mature livrează săptămânal fără să-și sperie clienții și fără seri de vineri petrecute cu sufletul la gură.

De ce contează pentru afacerea ta

✓Retragere instantanee la probleme

O funcționalitate care face probleme se stinge dintr-un click, în secunde — nu mai aștepți o lansare de urgență și nu mai anunți clienții de mentenanță neplanificată.

✓Lansări graduale, risc controlat

Noutatea ajunge întâi la 5% din utilizatori; dacă cifrele arată bine, procentul crește — o eroare scăpată afectează o mână de clienți, nu toată baza.

✓Marketingul decide momentul, nu IT-ul

Funcția stă gata în producție și se aprinde exact la ora campaniei de lansare — sincronizarea dintre promovare și livrare nu mai depinde de calendarul tehnic.

Cum funcționează un feature flag

Codul aplicației întreabă, în timpul rulării, un serviciu de flag-uri sau o configurare: „funcționalitatea X este activă pentru acest utilizator?”. Răspunsul depinde de un context de evaluare: identificatorul utilizatorului, țara, planul contractat, dispozitivul. În cod arată simplu: „dacă flags.activ("checkout-nou", utilizator) atunci arată checkoutul nou, altfel pe cel vechi”.

Regulile obișnuite sunt: activ sau inactiv pentru toți, activ pentru un procent de utilizatori (lansare graduală), activ pentru o listă de conturi și un kill switch, adică un flag care oprește în producție o parte care se strică. Starea flag-urilor poate sta într-un rând din baza de date, într-o proprietate dintr-un fișier de configurare sau într-un serviciu extern (Wikipedia, „Feature toggle”).

Fiecare flag dublează căile prin cod: ambele ramuri trebuie testate, de aceea feature flag-urile merg împreună cu testele de regresie.

Tipuri de feature flags și cât trăiesc

Pete Hodgson, pe martinfowler.com (2017), împarte flag-urile în patru categorii după cât timp trăiesc. Release toggles sunt temporare și se șterg după lansare. Experiment toggles susțin un test A/B și trăiesc până se termină testul. Ops toggles controlează comportamentul operațional, de pildă dezactivarea unei funcții sub încărcare mare; majoritatea sunt de scurtă durată, câteva se păstrează intenționat. Permissioning toggles dau funcții doar utilizatorilor premium sau beta și pot trăi ani.

Regula de igienă: fiecare flag primește un responsabil și o dată de expirare, iar ștergerea lui face parte din terminarea funcției. Un flag uitat nu e doar cod în plus. În 1 august 2012, Knight Capital a pierdut peste 460 de milioane de dolari în aproximativ 45 de minute: codul nou refolosea un flag care activase cândva o funcție abandonată din 2003, iar unul dintre cele opt servere nu primise codul nou (SEC, ordinul 34-70694 din 16.10.2013).

Feature flag vs feature toggle, configurare, branch și deploy

Feature flag, feature toggle, feature switch și feature gate sunt sinonime pentru aceeași tehnică (Wikipedia). O valoare de configurare statică este aceeași pentru toți și de obicei cere repornire sau redeploy. Un flag se evaluează pentru fiecare cerere sau utilizator și se schimbă fără repornire.

Față de un feature branch de lungă durată, flag-ul permite să unești cod nefinalizat în ramura principală, ascuns în spatele unui flag. Asta e dezvoltarea pe trunchi comun (trunk-based development) și sprijină fluxul de integrare continuă. Cât despre deploy: deploy-ul pune codul în producție, flag-ul decide cine îl vede. Tema completă a deploy-ului e tratată în dicționar la termenul deployment.

OpenFeature: standardul deschis pentru feature flags

OpenFeature este o specificație deschisă, dezvoltată de comunitate, cu un API și un SDK neutre față de furnizor pentru evaluarea flag-urilor. Funcționează cu unelte comerciale, unelte open-source sau cu un sistem propriu, prin „provideri”. Componentele SDK-ului sunt: Evaluation API, Evaluation Context, Providers, Hooks și Events.

Pentru un IMM contează simplu: codul apelează un singur API, deci schimbarea furnizorului de flag-uri sau trecerea de la un tabel propriu la un serviciu nu înseamnă rescrierea fiecărui test de flag din cod. Nu rămâi legat de un furnizor la nivel de cod.

OpenFeature este proiect CNCF, acceptat la 17.06.2022 și în faza incubating din 21.11.2023, sub licență Apache 2.0. Verificat la 18 noiembrie 2026 pe openfeature.dev și cncf.io.

Întrebări frecvente

Ce înseamnă feature flag în română?

Nu există un termen românesc consacrat. Literal ar fi „steag de funcționalitate”, în practică se spune „comutator de funcționalitate”. Se mai numește feature toggle, feature switch sau feature gate și pornește ori oprește o funcție din aplicație fără o nouă lansare.

Care este diferența dintre feature flag și feature toggle?

Nicio diferență tehnică: sunt două nume pentru aceeași tehnică (Wikipedia; articolul lui Pete Hodgson de pe martinfowler.com se numește „Feature Toggles (aka Feature Flags)”). LaunchDarkly le separă doar terminologic: toggle este practica, flag este mecanismul din cod.

Cu ce se administrează feature flag-urile?

De la o simplă configurare proprie în baza de date până la platforme dedicate ca LaunchDarkly, Unleash sau Flagsmith, care oferă interfață pentru nespecialiști, procente de rollout și istoricul fiecărei comutări. Cu OpenFeature, același cod din aplicație funcționează cu oricare dintre aceste unelte.

Feature flag-urile complică întreținerea codului?

Dacă rămân uitate, da — codul se umple de ramificații moarte. Practica sănătoasă e ca fiecare flag să aibă un «termen de viață»: după ce funcția e activată pentru toți și stabilă, flag-ul se șterge din cod.

Pot folosi feature flags pentru teste A/B?

Da, e una dintre utilizările principale: jumătate din utilizatori văd varianta A, jumătate varianta B, iar platforma măsoară care convertește mai bine — decizia de produs se ia pe cifre, nu pe intuiția celui mai vocal din ședință.

Ce este OpenFeature?

OpenFeature este o specificație deschisă și un SDK pentru feature flags, proiect CNCF aflat în faza incubating din 21.11.2023. Oferă un API neutru față de furnizor pentru evaluarea flag-urilor, deci schimbi furnizorul fără să modifici verificările de flag din cod.
