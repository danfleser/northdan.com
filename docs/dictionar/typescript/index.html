Ce este TypeScript?

JavaScript cu tipuri de date declarate și verificate înainte de rulare: greșelile apar în editor, nu la utilizatori.

TypeScript este un limbaj de programare open source, dezvoltat de Microsoft, care adaugă peste JavaScript tipuri statice opționale, verificate înainte de rulare, și care se transformă apoi în JavaScript obișnuit. Este un superset: orice cod JavaScript valid este, în mare, și TypeScript valid, iar tipurile dispar complet din codul care rulează. Versiunea curentă este TypeScript 7 (7.0 a apărut pe 8 iulie 2026), primul compilator rescris nativ, în Go, de aproximativ 10 ori mai rapid. Din 2025, TypeScript este și limbajul cu cei mai mulți contributori lunari pe GitHub (Octoverse 2025 și 2026). Verificat la 18 noiembrie 2026.

Pentru o firmă care comandă o aplicație, tipurile sunt documentație care nu se învechește și plasa de siguranță a modificărilor: schimbi structura unei date și compilatorul arată fiecare loc de actualizat, înainte de livrare. Adopția poate fi graduală, fișier cu fișier, iar codul rulează oriunde rulează JavaScript. Pe un proiect mic diferența ține de gust; pe o aplicație de business cu mai mulți programatori și ani de întreținere, ea se simte la fiecare modificare.

De ce contează pentru afacerea ta

Erori prinse la scriere, nu la clienți

Categorii întregi de defecte — date greșite, câmpuri lipsă, apeluri incompatibile — mor în editorul dezvoltatorului, înainte de orice livrare.

Modificări cu hartă completă

Schimbarea unei structuri de date arată automat fiecare loc de actualizat — regresiile tăcute ale modificărilor „mici” dispar structural.

Cod care se explică singur

Tipurile sunt documentație vie și mereu actuală — echipele noi și schimbările de furnizor pornesc din semnături clare, nu din ghicit.

Cum funcționează TypeScript: tipuri, verificare, compilare

Programatorul adaugă adnotări de tip: ce date primește și ce întoarce o funcție. În multe locuri compilatorul deduce tipul singur (inferență), iar structurile de date se descriu cu interfețe. Exemplu: în funcția `function totalCuTva(suma: number, cota: number): number`, apelul `totalCuTva("100", 21)` este semnalat ca eroare în editor, pentru că suma e text, nu număr. În JavaScript simplu, apelul rulează fără niciun avertisment și, dacă funcția adună (de exemplu suma + suma * cota / 100), dă „10021” în loc de 121.

Compilatorul `tsc` (sau un instrument de build) verifică tipurile, șterge adnotările și produce JavaScript. Erorile de tip se raportează la compilare, nu la rulare. Tipul `any` oprește verificarea pentru valoarea respectivă, de aceea folosirea lui peste tot anulează beneficiul.

TypeScript și JavaScript: diferența

Rulează același cod JavaScript, în același browser sau în același Node.js, cu aceleași biblioteci. TypeScript adaugă două lucruri: tipurile și un pas de compilare. Pentru câteva scripturi pe un site de prezentare, JavaScript simplu este suficient. TypeScript se justifică de la o aplicație de business întreținută de mai mulți oameni, pe ani.

Pagina Dezvoltare JavaScript explică ce păstrăm și ce curățăm într-un front-end JavaScript moștenit; pagina Dezvoltare TypeScript, cum migrăm un proiect existent fișier cu fișier.

TypeScript 7 și compilatorul nativ

TypeScript 7.0, lansat pe 8 iulie 2026, este portul nativ al compilatorului, scris în Go. Se instalează tot ca pachetul npm `typescript`, iar comanda rămâne `tsc`. Microsoft raportează build-uri complete de obicei de 8 până la 12 ori mai rapide decât în 6.0 (de exemplu 11,9 ori pe codul VS Code). Modul `strict` rămâne activ implicit, ca din 6.0, iar opțiunile `target: es5`, `baseUrl`, `downlevelIteration` și `moduleResolution: classic` au fost eliminate. TypeScript 6.0 (23 martie 2026) este ultima versiune pe vechiul compilator, care rula ca JavaScript.

Ce nu merge încă în 7.0: versiunea nu are API programatic, iar verificarea șabloanelor Vue, Svelte, Astro, MDX și Angular nu funcționează; pentru aceste proiecte Microsoft recomandă TypeScript 6.0, care rulează în paralel prin pachetul `@typescript/typescript6` (comanda `tsc6`). TypeScript 7.1 Beta (20 octombrie 2026) aduce API-ul nou și primele adaptoare pentru Vue, Svelte, Astro și MDX (prototipuri sau implementări inițiale); versiunea candidat e anunțată pentru „aproximativ o lună”, fără dată, iar cea finală la scurt timp după.

Pentru beneficiar: un proiect vechi pe TypeScript 5.x nu este o urgență, dar un furnizor trebuie să poată spune pe ce versiune lucrează și de ce.

Fișiere .ts rulate direct în Node.js

Browserele nu rulează TypeScript, dar Node.js da: începând cu v23.6.0 și v22.18.0 poate rula fișiere .ts fără pas de compilare, iar funcția este stabilă din v25.2.0 și v24.12.0. Linia curentă cu suport pe termen lung (LTS) este Node.js 26. Afirmația răspândită că „TypeScript nu rulează direct în motoarele JavaScript” este depășită pentru Node.js.

Node.js doar șterge tipurile, nu le verifică. Nu citește tsconfig.json, nu rulează sintaxa care produce cod la rulare (`enum`, `namespace` cu cod, proprietăți declarate în constructor), cere extensia `.ts` în importuri și nu suportă `.tsx`. Verificarea tipurilor rămâne sarcina lui `tsc --noEmit` în build sau în CI, iar în browser compilarea rămâne necesară.

Ce înseamnă TypeScript pentru o firmă care comandă o aplicație

Oferta „construim în TypeScript” este practică normală, nu un moft de tarif: Next.js, de exemplu, creează implicit proiecte TypeScript. O aplicație moștenită în JavaScript nu se rescrie; în practica noastră se migrează gradual, odată cu mentenanța.

Întrebarea de calitate la contractare: „TypeScript strict sau doar cu numele?”. De la TypeScript 6.0, `strict` este activ implicit (și în 7.0), deci un `"strict": false` în tsconfig.json înseamnă că cineva l-a oprit intenționat. Merită cerută explicația.

Întrebări frecvente

TypeScript scumpește dezvoltarea?⌄

Puțin la scriere, pentru că declarațiile de tip cer efort, mai puțin cu uneltele actuale. În experiența noastră se câștigă la întreținere: mai puține defecte în producție, modificări mai sigure, integrare mai rapidă a oamenilor noi. Nu este o cifră măsurată, ci practica proiectelor pe care le-am livrat.

Aplicația noastră existentă e în JavaScript: trebuie rescrisă?⌄

Nu. TypeScript permite adopția graduală: fișierele se migrează individual, iar JavaScript și TypeScript coexistă în același proiect. În proiectele noastre tipice, codul atins la mentenanță și funcțiile noi se scriu tipizat, restul așteaptă. Cereți verificările stricte pe codul nou, ca migrarea să livreze plasa, nu doar extensia de fișier.

Ce înseamnă „TypeScript strict” și de ce să-mi pese?⌄

Modul strict impune declararea onestă a tipurilor și tratarea cazurilor „poate lipsi”. De la TypeScript 6.0 (23 martie 2026) este activ implicit, iar 7.0 păstrează regula, deci `"strict": false` în tsconfig.json înseamnă că cineva l-a oprit intenționat; cereți explicația. Un auditor verifică asta în câteva minute, la fel și folosirea excesivă a lui `any`.

TypeScript sau JavaScript: care e mai bun?⌄

Niciunul în general, pentru că rulează pe același motor. JavaScript simplu este suficient pentru scripturi mici. TypeScript câștigă la aplicații întreținute de mai mulți oameni pe ani, unde tipurile previn erorile de modificare. Alegerea ține de dimensiunea și durata de viață a proiectului.

Mai merită TypeScript în 2026?⌄

Da. Conform GitHub Octoverse 2026 (28 octombrie 2026), TypeScript este cel mai folosit limbaj după numărul de contributori lunari, al doilea an la rând. Are compilator nativ din TypeScript 7.0, iar Next.js creează proiecte TypeScript implicit. Metrica este numărul de contributori, nu liniile de cod.

Care este cea mai nouă versiune de TypeScript?⌄

La 18 noiembrie 2026, versiunea stabilă din npm este 7.0.2 (publicată pe 8 iulie 2026), iar 7.1 este în beta din 20 octombrie 2026. TypeScript 6.0 (martie 2026) este ultima versiune pe vechiul compilator, care rula ca JavaScript. Verificați pachetul `typescript` pe npm pentru starea la zi.

Poate rula un browser sau Node.js cod TypeScript direct?⌄

Browserul nu. Node.js da, de la v22.18.0 și v23.6.0, dar doar șterge tipurile, fără să le verifice. Verificarea rămâne la `tsc --noEmit`. Nu sunt suportate `enum`, `namespace` cu cod la rulare și `.tsx`, iar importurile cer extensia `.ts`.
