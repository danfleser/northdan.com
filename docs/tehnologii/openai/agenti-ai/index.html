Agenți AI pe modelele OpenAI: unelte legate de sistemele firmei, aprobare umană, cost plafonat

Un agent pe modelele OpenAI primește o sarcină, alege singur unealta potrivită și o execută în sistemele firmei, cu aprobare umană la pașii sensibili.

Un agent AI pe modelele OpenAI, construit la comandă, costă orientativ 3.000–8.000 € ca pilot pe o singură sarcină, plus 20–500 €/lună consum de API la volume de IMM, și se potrivește când sarcina trece prin mai multe sisteme și cererile vin formulate liber. Mecanismul este apelarea de funcții: modelul primește o listă de unelte — interoghează stocul, creează factura proformă, trimite e-mailul de confirmare — și decide singur pe care o folosește, în ce ordine și cu ce parametri, până când sarcina primită e îndeplinită.

OpenAI oferă azi trei moduri de a rula un agent: Agents API, unde OpenAI rulează agentul și își păstrează sesiunile; Agents SDK, unde bucla rulează în aplicația voastră, iar stocarea și aprobările rămân la voi; și Responses API, apeluri directe la model, cu bucla scrisă de la zero. Pentru agenții care scriu în ERP sau CRM folosim Agents SDK, pentru că aprobările și jurnalele rămân de partea voastră. SDK-ul rulează și modele de la alți furnizori, deci stratul de unelte supraviețuiește unei schimbări de furnizor. Modelele greșesc, de aceea fiecare unealtă are validări proprii, acțiunile cu consecințe cer aprobare umană, costurile au plafoane, iar fiecare rulare lasă un jurnal complet.

Ce primești

Cereri formulate liber, documente neuniforme

Cererile clienților nu vin în format standard: agentul pe modelele OpenAI înțelege formulări libere, documente neuniforme și informații incomplete — cazuri care blochează automatizările pe reguli fixe.

Unelte cu validări proprii

Agentul nu primește acces brut la sisteme, ci unelte definite de noi, fiecare cu validări și limite proprii. Chiar și un model care greșește nu poate face decât ce uneltele îi permit.

Aprobare umană la pașii ireversibili

Plăți, comunicare către clienți, modificări ireversibile: în Agents SDK o unealtă marcată cu needs_approval oprește rularea până aprobă un om, apoi rularea continuă din același punct. Agentul pregătește totul, omul dă clic.

Codul, uneltele și jurnalele rămân ale voastre

Primiți codul sursă, cheia API pe contul OpenAI al firmei, istoricul rulărilor exportabil și documentația uneltelor. Dacă schimbați furnizorul sau colaborarea, nu pierdeți nimic din ce s-a construit.

Ce construim pe modelele OpenAI

Stratul de unelte peste sistemele firmei (API, bază de date, e-mail, fișiere), bucla agentului pe Agents SDK cu verificări de intrare și ieșire, puncte de aprobare umană și urmărirea fiecărui pas, plus un panou cu rulările: ce a făcut agentul, ce a cerut aprobare, ce a eșuat. Scenarii tipice: cererile de ofertă sosite liber pe e-mail (agentul extrage cerințele, caută în catalog, verifică stocul și pregătește oferta pe care omul de vânzări o revizuiește), suportul de nivel unu (identifică clientul, verifică istoricul comenzii, rezolvă cazurile standard și predă cazurile grele cu dosarul făcut) și raportarea lunară din mai multe sisteme, cu semnalarea discrepanțelor.

Primul agent se alege după trei criterii: volum mare, reguli clare, cost mic al greșelii. Un bun candidat este concordanța comandă–aviz–factură. Autonomia crește treptat: la început agentul propune și omul aprobă; categoriile cu jurnal curat trec pe execuție directă, iar plățile, ștergerile și comunicarea externă sensibilă rămân la om. Dimensionăm întâi un pilot pe o singură sarcină, măsurat contra procesului manual pe precizie, timp economisit și cost pe sarcină; cifrele din pilot decid extinderea.

Agent în ChatGPT sau agent construit pe API — când e potrivit fiecare

Agenții configurați direct în ChatGPT sunt suficienți când munca rămâne în ChatGPT și în aplicațiile la care se conectează, chiar dacă rulează după un program sau pornesc din Slack. Un agent construit pe API e potrivit când trebuie să scrie în ERP sau CRM cu validările voastre, să-și logheze fiecare pas în sistemele voastre, să ruleze pe infrastructura voastră sau să poată trece la alt furnizor de modele.

Dacă sarcina urmează reguli fixe și rulează de câteva zeci de ori pe lună, o automatizare clasică e mai ieftină și mai previzibilă decât un agent. Diferența dintre un chatbot și un agent este explicată separat, în dicționar.

Pe ce rulează agentul și ce s-a schimbat la OpenAI în 2026

Alegerea dintre Agents API, Agents SDK și Responses API se face după cine ține bucla și datele: cu Agents API, OpenAI rulează agentul și păstrează sesiunile (efort de integrare mic, control mai mic); cu Agents SDK, voi țineți deploy-ul, stocarea și aprobările (efort mediu); cu Responses API scrieți bucla singuri (efort mare, control maxim).

Riscul de platformă e real: OpenAI a oprit Assistants API pe 26.08.2026, la un an după anunțul din 26.08.2025, cu Responses API și Conversations API ca înlocuitor. Agenții construiți direct pe el au trebuit mutați. De aceea ținem uneltele și regulile de business separate de runtime, iar o schimbare de runtime atinge un singur strat.

Cât costă, orientativ

Prețurile sunt fără TVA. Un pilot sau prototip pe un singur caz costă 3.000–8.000 €. Un agent conectat într-o aplicație existentă, care citește și scrie în ea, costă 3.000–15.000 €. O funcționalitate dedicată peste datele interne, cu mai multe fluxuri, costă 10.000–50.000 €. Prețul se mută după numărul de sisteme în care scrie agentul, după validările și confirmările umane și după calitatea datelor de pornire.

Costurile recurente: API-ul modelului 20–500 €/lună la volume de IMM și 50–1.000 €+/lună la volume mari, găzduire cloud gestionată 50–300 €/lună și întreținere de 15–20% pe an din costul dezvoltării. Costul de API se ține sub control cu modele mai mici pe pașii simpli, plafoane zilnice cu alertă și oprire automată la bucle.

Întrebări frecvente

Cât costă un agent AI pe modelele OpenAI?⌄

Orientativ 3.000–8.000 € pilotul pe o singură sarcină și 3.000–15.000 € agentul care scrie într-o aplicație existentă, fără TVA. La ele se adaugă 20–500 €/lună consum de API la volume de IMM și 15–20% pe an întreținere din costul dezvoltării. Prețul final depinde de numărul de sisteme și de validări.

Ne ajung agenții din ChatGPT sau avem nevoie de un agent construit pe API?⌄

Agenții din ChatGPT ajung când munca rămâne în ChatGPT și în aplicațiile la care se conectează, chiar dacă rulează după un program sau pornesc din Slack. Agentul construit pe API e necesar când trebuie să scrie în ERP sau CRM cu validările voastre, să-și logheze fiecare pas în sistemele voastre, să ruleze pe infrastructura voastră sau să poată schimba furnizorul de modele.

Un agent pe modelele OpenAI poate lucra cu sistemele noastre existente?⌄

Da, cu condiția să existe o cale programatică de acces: API, bază de date sau măcar export-import de fișiere. Construim stratul de unelte peste ce aveți. Ca să pornim, ne trebuie un mediu de test, un responsabil de proces și cazuri istorice cu rezultatul corect. Un flux delimitat durează orientativ 4–6 săptămâni.

Ce rămâne la noi dacă schimbăm furnizorul de modele sau renunțăm la colaborare?⌄

Rămân codul sursă, uneltele, jurnalele rulărilor și cheia API de pe contul firmei voastre. Agents SDK rulează și modele de la alți furnizori, deci stratul de unelte și regulile de business se pot muta pe alt model fără să fie rescrise.

Ce se întâmplă când OpenAI retrage API-ul pe care rulează agentul?⌄

Se mută un singur strat. Assistants API a fost anunțat pentru oprire pe 26.08.2025 și oprit pe 26.08.2026, înlocuit de Responses API. Cu uneltele separate de runtime, mutarea rescrie stratul de rulare, nu agentul și nici regulile de business.
